# Phase 2 Model-config Migration

## Summary

Implemented the Phase 2 slim model module as a facade-preserving migration.

- Added `src/ModelConfig/ModelConfigModule.f90` with `ModelConfigType` and the public `modelConfig` singleton.
- Moved model-level namelist reads for `/data/`, `/output/`, `/run/`, optional `/checkpoint/`, optional `/steady_state/`, and batch `/batch_config/` + `/chunks/` into `ModelConfigModule`.
- Updated `src/GlobalsModule.f90` so `GLOBALS_INIT` delegates model-level config to `modelConfig`, then mirrors values back into `C`.
- Kept domain namelist reads (`/soil/`, `/sediment/`, `/water/`, `/sources/`) in `GLOBALS_INIT` for later domain phases.
- Updated batch chunk switching and checkpoint-preserved timestep handling so runtime mutations update `modelConfig` first, then sync the `C` facade.

## Fields Moved

`ModelConfigModule` now owns:

- Data paths: `inputFile`, `constantsFile`, `outputPath`, `outputHash`.
- Output controls: CSV/NetCDF flags, NetCDF write mode, output breakdown flags, PEC unit strings.
- Run controls: timestep, timestep count, start date, warm-up period, epsilon, logging flags/path, warning/error flags, simulation mask state, `ignoreNM`, `bashColors`, model version.
- Checkpoint controls: checkpoint file, save/reinstate flags, `preserveTimestep`, and `t0`.
- Steady-state controls: mode, enabled flag, and delta threshold.
- Batch state: batch file arrays, batch dates/timesteps, chunk count, current chunk paths/date/timestep count, and batch start/end summary dates.

The old `C%...` fields are still populated from `modelConfig` so unmigrated model, data, logger, and domain code keep compiling and keep existing behavior.

## Notes

- `ModelConfig%audit()` returns a `Result` instead of triggering `ERROR_HANDLER` directly. This avoids a dependency cycle because `ERROR_HANDLER` still lives in `GlobalsModule`.
- `errorOutput` is now represented in `ModelConfigType` and mirrored into `GlobalsType` for the `ERROR_HANDLER%init(..., on=...)` call.
- `ModelConfigType` component initializers are neutral pre-init state only. The authoritative default reset happens in `clearModelConfig`, which copies model-level defaults from `DefaultsModule%configDefaults` before any namelist read.
- The model-level `epsilon` default was moved into `DefaultsModule%configDefaults` and `ModelConfigModule` now reads it from there.
- The model-level `triggerWarnings`, `errorOutput`, and `simulationMask` defaults are also read from `DefaultsModule%configDefaults`; `hasSimulationMask` remains derived from whether the effective simulation-mask path is empty.
- Phase 2 does not split or replace `DefaultsModule`. `GlobalsModule` still uses it for unmigrated domain defaults until the per-domain phases move `/soil/`, `/sediment/`, `/water/`, and `/sources/`.
- `DataInputModule%updateDatabase` now calls `modelConfig%selectBatchChunk(k)` before syncing the facade.
- `CheckpointModule%reinstate` now calls `modelConfig%setT0(t)` before syncing the facade when `preserve_timestep` is true.
- `batchConfigFiles` remains unallocated, matching the pre-Phase-2 behavior.

## Deferred By Design

- Domain config/default ownership remains deferred to the per-domain phases.
- `LoggerModule`, output modules, `main.f90`, and science domains still read model config through `C`.
- `ERROR_HANDLER` and the flat error array remain in `GlobalsModule`; the existing duplicate `errors(11)` assignment is unchanged in this phase.
- `VersionModule.f90` remains generated by CMake. The facade keeps the historical 16-character model-version field, so builds may warn about truncating the generated 17-character version string.
