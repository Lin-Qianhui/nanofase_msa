## What was wrong

1. **An empty access mode became a write in the DOT exporter.** The old code
   selected `W` whenever neither its read nor write flag was set. PSyclone 3.2.2
   reports references in declaration bounds, including `npDim`, with access
   type `CONSTANT`. The old script converted those to an empty string. Six of
   the seven `npDim` writer edges came from this bug: AbstractBedSediment,
   Checkpoint, Util, EstuaryReach, Reach, and RiverReach. These uses are reads.
2. **Passing an argument could produce a conservative read/write estimate.**
   PSyclone's call analysis attempts to resolve the callee, but falls back to
   `READWRITE` when it cannot. The script parsed each file independently and
   did not build a complete cross-file interface index. Unsupported PSyIR
   `CodeBlock` contents also receive conservative `READWRITE` estimates.
   Those estimates were presented as ordinary writes.
3. **Imports were only partially resolved.** The old analysis accepted explicit
   `ImportInterface` symbols and skipped other unresolved bindings. It did not
   systematically resolve wildcard `use`, renamed imports, re-exports, private
   visibility, or local shadowing. Its fallback chose the first alphabetical
   candidate owner when several modules provided a name.
4. **Components had partial, inconsistent coverage.** Pass 2 attempted type
   resolution, but the DOT graph discarded component paths and displayed only
   root variables. Its declaration scan recovered only imported derived roots,
   not ordinary mutable dimensions. PSyIR failure in the old pre-migration
   GridCell module also caused reduced fallback coverage.
5. **Reports and DOT aggregation disagreed.** Text could contain separate `R`,
   `W`, `RW`, and empty rows for the same relationship. Home-module casing could
   split one module into separate graph nodes. Global routine-name filtering
   could also remove an unrelated variable with the same name.

The revised extractor uses fparser2 directly, with a shared index of module,
procedure, interface, type, and use-association declarations. It no longer
depends on PSyclone's conservative access classifications or a coarse fallback.
Constants, procedure names, and type names do not become state nodes.

## Verified `npDim` result

Both baselines have **one writer module and 17 reader modules**, with no uncertain
`npDim` effects:

- Current: `ModelDimensionsModule::npDim`, written by `ModelDimensionsModule` at
  [the dimension initialization](../src/ModelDimensions/ModelDimensionsModule.f90#L107)
  and reset at line 129.
- Before migration: `GlobalsModule::C%npDim`, written by `GlobalsModule` at line
  428 of that tree's `src/GlobalsModule.f90`.

This result includes specification-expression reads in abstract interfaces and
local array bounds, as well as reads in executable statements and allocations.
Every recorded state access has a source path, line, statement, and reason in
the JSON, together with source SHA-256 hashes. `coverage.json` records these
writer/reader lists and the coverage counts.

## Meaning of the edges

- `R`: value read, specification-expression dependency, or `intent(in)` argument.
- `W`: assignment, initialization, allocation/deallocation, I/O output into a
  variable, or `intent(out)` argument.
- `RW`: both kinds of access, or `intent(inout)`.
- `?`: an unresolved effect. It is **not a write**. An edge containing `?` is
  dashed. `?` alone has no arrow; `R?`/`RW?` retain the known directions while
  indicating additional uncertainty.

These are static **may-access** relationships, not a runtime execution trace:
branches are unioned, and an output intent permits a modification without proving
that every execution modifies the value. Index and allocation-bound expressions
are reads, even when the indexed object is written. Keyword arguments and
`PASS`/`NOPASS` are mapped to the correct dummy arguments. When an implementation
has no `intent`, its dummy effects are inferred through calls to a fixed point.
Conflicting generic candidates and unresolved deferred interfaces retain `?`.
For polymorphic receivers, known overriding implementations are also considered.

State nodes preserve the defining instance and component path, for example
`globalsmodule::c%npdim`, rather than combining every instance of a type. Array
elements are aggregated into the same path. Whole-object call effects use the
root node and can overlap component nodes; do not treat those as disjoint memory
locations when calculating later metrics.

The separate type-dependency section records accesses through local objects and
dummies as well as imported instances. Its labels use the root's declared type
and the path below it, including inherited/nested components. A local object of
an imported type is not automatically shared state. `ASSOCIATE` variable aliases
and `SELECT TYPE` narrowing are handled in their lexical scopes.

## Coverage and remaining uncertainty

All **47 pre-migration files** and **58 current files** parse successfully. Both
trees have zero unresolved-symbol, unresolved-component, or unsupported-statement
diagnostics in this run. Source discovery excludes directories named `test`,
`tests`, `example`, and `examples`; it does not include build products. Duplicate
modules and parse errors fail generation instead of silently reducing coverage.

The current shared-state graph has four relationships containing `?`:

- `BootstrapModule` and `main` accessing the whole `DataInputModule::DATASET`:
  known read/write effects coexist with unresolved effects through its callees,
  including the unavailable NetCDF interfaces.
- `EstuaryReachModule` and `RiverReachModule` passing `DATASET%shearRate` through
  the deferred reactor update interface, which declares no intent for `G`.
  The concrete Reactor implementation reads `G`, but this analysis does not
  assume that an abstract receiver has that particular dynamic implementation.

The pre-migration graph has three such relationships: the same two `shearRate`
relationships and `main`'s whole-object `DATASET` access. Other diagnostics concern
local/dummy objects and unavailable callee effects; their counts and exact sites
are in the JSON. Thirteen pointer-association sites in each tree are explicitly
flagged: the tool does not propagate subsequent accesses through arbitrary
pointer/heap aliases. Consequently these graphs are an auditable source-level
baseline, not a proof of complete runtime memory flow.

Additional limits: supplied sources are assumed to be valid Fortran; external
wildcard modules cannot have their exports verified, so known internal/host
declarations take precedence over hypothetical external exports. Unavailable
module names are listed in JSON. This is not a full compiler: overload selection
uses keyword/arity compatibility and agreement of effects, not complete
type/kind/rank resolution. Unsupported statements are diagnosed with uncertain
references. Preprocessing, COMMON/EQUIVALENCE alias analysis, and arbitrary
procedure-pointer targets are not resolved. Direct global accesses are attributed
to the module containing them; they are not copied onto every transitive caller.

For later comparison, use the same source scope and options for both trees and
decide explicitly whether to include uncertain edges, whole-object effects, and
type dependencies. The original root-level graphs are not equivalent inputs.

## Reproduce

The existing `.venv` has fparser 0.2.1; Graphviz is needed only for rendering SVGs.
No model build, model execution, network access, or PSyclone dependency is needed.

```sh
.venv/bin/python -B -m unittest -v test_fortran_dataflow
.venv/bin/python -B dataflow/regenerate.py \
  --pre-root /Users/qianhuilin/Documents/nanofase_before_migration/nanofase
```

The regeneration script writes only this directory by default, and reads the
source trees. Use `--output-dir`, `--post-root`, or `--no-render` as needed. It
generates both baselines with `--ignore omp_lib netcdf spoof --strict --no-external`.
Ignored modules still supply interfaces when their source is available.

To regenerate just the current full graph:

```sh
.venv/bin/python -B fortran_dataflow.py --src src vendor \
  --ignore omp_lib netcdf spoof --strict --no-external \
  -o dataflow/flow_postmigration.dot -r dataflow/flow_postmigration.txt \
  --evidence dataflow/flow_postmigration.json
dot -Tsvg dataflow/flow_postmigration.dot -o dataflow/flow_postmigration.svg
```

The 18 regression tests exercise import resolution and shadowing, array bounds,
component paths, local versus shared objects, call intent and keyword mapping,
body-effect inference, polymorphic overrides, generic constructors, allocation,
I/O, alias scopes, uncertain effects, source discovery, parse failures, and the
empty-mode DOT regression.
